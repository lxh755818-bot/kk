### 1.3 核心问题根因

```
皇上(小豪)
    ↓ 自然语言

    ↓ DM未打通
门下省(二虾) → 审议 ❌ 从未激活

    ↓
户部/工部     → 操作 ❌ 无健康检查
```

**三个断层**：
1. **信任链断层**：各省之间无直接通信协议，消息全部过皇上
2. **执行层断层**：尚书省无健康检查、无重试机制、无降级方案
3. **异常链断层**：异常发生后没有自动上报和恢复流程

## 三、优化方案

### 3.1 打通信任链（DM通道）

**现状**：所有消息经过皇上转发
**目标**：各省之间直接通信，皇上只接收最终结果

```
优化后链路：
皇上(小豪) ← 最终结果 ← 各省协作 ←→ 各省直接沟通
     ↓ 任务下发              ↓ 直接沟通
中书省(大虾) ←──────→ 门下省(二虾)
     ↓                        ↓
尚书省(三虾) ←──────→ 户部/工部
```

**实施步骤**：
1. 为每个Agent配置独立的飞书机器人/webhook
2. 建立 DM 消息格式标准：`[来源省]→[目标省]: 内容 #trace_id`
3. 皇上设置消息过滤规则：只接收「需决策」和「异常上报」两类

### 3.2 尚书省健康检查机制

**现状**：执行层无监控，失败了也不知道
**目标**：像看门狗一样监控，发现问题自动重试/降级

```python
# 尚书省健康检查伪代码
class 执行层监控:
    def check_health():
        - Checkpoint仓库访问 ✓/✗
        - MCP minimax连接 ✓/✗
        - Mem0同步状态 ✓/✗
        - Feishu连接池 ✓/✗

    def auto_recover():
        - 访问拒绝 → 清理缓存 + 重试(3次)
        - 连接超时 → 指数退避重连
        - 服务不可用 → 降级到备用方案
```

**实施步骤**：
1. 在 `gateway/run.py` 中添加健康检查模块
2. 配置 `watchdog` 与尚书省联动
3. 异常自动上报格式：`[尚书省] 执行异常 #trace_id | 原因 | 已尝试`

### 3.3 异常分级与上报机制

**分级标准**：
| 等级 | 定义 | 上报方式 | 示例 |
|------|------|----------|------|
| L1 | 可自动恢复 | 不上报 | 连接超时重试成功 |
| L2 | 需要注意 | DM至尚书省 | 访问拒绝(已重试3次) |
| L3 | 需要干预 | DM至皇上 | 服务完全不可用 |

**飞书连接异常处理**：
```python
# 当前：重试3次失败后直接放弃
# 优化后：
def feishu_send_with_fallback():
    try:
        primary_send()
    except ConnectionReset:
        wait(1s) → retry
    except L3Error:
        fallback_to_new_message()
        notify_皇上()
```

### 3.4 沟通效率优化

**现状**：30分钟轮询太慢，实时推送太频繁
**优化方案**：事件驱动 + 批量汇总

| 场景 | 触发条件 | 通知方式 |
|------|----------|----------|
| 正常 | 每2小时无异常 | 静默 |
| 有实质进展 | 完成重要步骤 | 飞书push |
| 异常 | L2及以上 | 立即飞书push |
| 每日汇总 | 每日18:00 | 飞书push |

## 四、紧急修复（P0级）

### 4.1 Gateway启动锁权限问题

```bash
# 检查锁文件
ls -la ~/.hermes/gateway-lock.json

# 修复权限（Windows）
icacls gateway-lock.json /grant:lxh75:RW

# 或删除锁文件重启Gateway
rm gateway-lock.json
```

### 4.2 MINIMAX_API_KEY 环境变量

```bash
# 在 ~/.hermes/.env 中添加
MINIMAX_API_KEY=your_api_key_here

# 或在 config.yaml 中配置
mcp:
  minimax:
    env:
      MINIMAX_API_KEY: your_api_key_here
```

### 4.3 Checkpoint仓库访问拒绝

```bash
# 检查仓库权限
icacls "C:\Users\lxh75\.hermes\checkpoint" /grant:lxh75:RW

# 或清理过期的checkpoint记录
python -m tools.checkpoint_manager --prune --force
```
